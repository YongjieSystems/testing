# 永捷團隊作業（v1.4.0）

前台仍使用 GitHub Pages；團隊登入、共用資料與交易在 Supabase 專案 `yongjie-service-workspace`。2026-10-18 已確認組織為 Free，未啟用付費方案。

## 角色與後端權限

| 同公司共用案件與客戶報價 | 全部 | 全部 | 僅技術分派或本人已發布路線涉及的案件摘要 | 僅本人已發布路線涉及的案件摘要 |

匿名訪客不能讀取或修改公司資料。角色每次由後端查詢啟用名單，不能透過自訂 user metadata、瀏覽器顯示或修改請求自行升權。所有資料表開啟 RLS，瀏覽器只有 SELECT 權限；寫入必須經過檢查角色、版本與狀態的交易函式。成本另表保存，不混入工程師案件摘要或客戶報價 JSON。

本機估價仍可使用，不代表雲端主管核准。登入不會掃描或批次上傳 localStorage。只有使用者按「同步目前估價至團隊」才會上傳當前案件；主管上傳時另包含該表單內部成本。後端忽略前端傳入價目及總額，使用公司資料庫價目計算；更新報價後撤銷原核准。已有雲端連結的表單以版本檢查保存，衝突回傳 HTTP 409，不覆寫同事修改；網路回應不明時先重新整理案件列表，勿重複建立。

## 初次登入與員工開通

初始主管：`yj-system@service5c.com.tw`。專案擁有者建立一次性挑戰後，開通服務只允許建立尚不存在的新帳號；開通連結由本人開啟，再自行設定至少 12 字元的密碼。密碼只送 Supabase Auth，不進報價、資料庫成本欄位、Git 或備份。瀏覽器使用 sessionStorage 保存該分頁登入狀態，可按登出清除。

後續由主管在「員工名單與權限」登錄姓名、電子郵件、角色及啟用狀態，再為新帳號產生一次性開通連結。主管須核對員工本人身分，私下交付連結；這個流程不會寄送郵件，電子郵件在此為公司管理的登入識別，不聲稱完成收件匣所有權驗證。不要把連結放公開文件或群組。開通連結的 hash 只位於 URL fragment，前台立刻移除並交由 Auth 驗證。

開通服務不會替既有 Auth 帳號重新產生登入連結、重設密碼或讓主管冒用其他已存在的帳號。既有帳號可由名單核准加入團隊並使用原密碼；遺失密碼、遺失已開通連結或跨階段開通失敗時，須由 Supabase 專案擁有者執行帳號恢復，不能反覆嘗試建立。需要郵件恢復流程時須另外配置正式 SMTP，本版未配置寄信服務。

最後一位已登入的啟用主管不能被停用或降級。停用／更換角色由後端即時生效，既有有效登入權杖也不能繞過；先前合法取得的本機資料不會因停用而遠端刪除。

## 集中排線

1. 客服確認完整取件及回送費用、約定時段，將估價同步到團隊。
2. 主管選取案件，填核准理由並核准最新報價；未核准或內容再次變更的案件不能執行取送任務。
3. 客服或主管建立路線草稿，選擇已開通且啟用的工程師／收送人員，依行程順序加入取件及回送站點。
4. 所有時間均以臺北時間輸入及顯示。站點開始／結束涵蓋該站作業，站點之間由排線人員預留交通時間。本版不計算即時路況、最佳路徑、車輛容量或自動 ETA。
5. 主管發布路線。交易會檢查同一人員時間重疊、重複取送任務、跨公司案件、最新報價核准、回送前取件安排等條件。已發布路線不直接編輯；沒有完成站點時可由主管填原因取消，另建路線。
6. 工程師／收送人員只能看到本人的已發布路線與必要案件摘要，依順序回報完成或無法完成。未完成取件不能回報回送完成；失敗必須填原因，可安排重跑，不能直接覆寫原紀錄。
7. 路線站點都回報後結束該路線；技術維修、收款與整案結案是不同階段，最後由主管填原因結案。不自動把收送完成當成修復完成。

同組織排線寫入及發布使用組織列鎖，避免兩人同時通過衝突檢查；案件與路線另用版本作樂觀鎖。技術分派使用獨立 assignment_version。列表約每 15 秒更新；輸入中暫停自動刷新，表單不被自動覆蓋。

## 已驗證與限制

- 既有估價／保固測試、嵌入式 PostgreSQL 測試覆蓋匿名拒絕、越權、跨公司隔離、成本隱私、價格竄改、版本衝突、排線時間／重複任務／順序、最後主管保護及開通 API 授權。
- 獨立 QA 團隊的真實雲端測試使用三種 Auth 帳號，驗證 13 項跨帳號操作；不寄信、不使用公司客戶資料。測試資料清除後不納入公司資料。
- 雲端畫面列最近 200 案與 100 條路線；資料庫不以此上限刪除資料，歷史查詢與分頁可再擴充。本機原有 200 筆上限及 JSON 備份仍獨立存在。
- 未建置自動雲端備份、SQL 還原介面、離線待傳佇列、郵件提醒、MFA 或對客戶的數位簽章。正式使用的備份與帳號恢復需由專案擁有者管理，不能把本機 JSON 備份當成完整雲端備份。
- Free 資源受供應商額度及供應條件限制，沒有升級或承諾付費服務等級。

## 安全檢查說明

Supabase advisor 對 authenticated 可呼叫 SECURITY DEFINER 函式提出通用提醒。本版刻意以這些函式實作角色檢查及原子交易：固定空 search_path、禁止匿名 EXECUTE、禁止直接寫表；私有輔助函式亦撤銷公開執行權限。每個入口均由權限測試確認 allow／deny，而非把通用提醒當成零風險證明。參考 [函式執行權限提醒](https://supabase.com/docs/guides/database/database-linter?lint=0029_authenticated_security_definer_function_executable)。

新專案的外洩密碼檢查尚未啟用；本版要求本人設定至少 12 字元密碼。供應商的額外密碼強化設定可參考 [密碼安全](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection)，若需付費方案須另行取得同意。
